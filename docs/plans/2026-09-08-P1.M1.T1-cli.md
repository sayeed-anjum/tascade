# Tascade CLI (P1.M1.T1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a thin `tascade` command-line client over the Tascade REST API so every
harness gets the same agent interface without paying MCP's per-turn schema cost (D2).

**Architecture:** A single declarative command table (`app/cli/commands.py`) is the one
source of truth: each entry names its subcommand path, HTTP method, URL template, argument
list, and the MCP tool it mirrors. `app/cli/main.py` builds argparse from that table;
`app/cli/client.py` performs the request over stdlib `urllib`; `app/cli/config.py` resolves
endpoint and key. The parity test walks the same table against `MCP_TOOL_NAMES`, so a new
MCP tool cannot land without a CLI command. Five REST endpoints missing from the server are
added so the table can be complete.

**Tech Stack:** Python 3.12 stdlib only for the client (`argparse`, `urllib.request`,
`tomllib`, `json`); FastAPI/Pydantic for the new endpoints; pytest + FastAPI `TestClient`.

**Spec:** `docs/design/2026-09-08-control-plane-for-herdr-agents.md` (D2, D4),
`docs/BACKLOG.md` slice 1 item 1 and the "Carried forward" section.

## Global Constraints

- The CLI is a **thin client over REST only**. `app/cli/*` must never import `app.store`,
  `app.mcp_tools`, or `app.main`. A test enforces this.
- Every subcommand accepts `--json` and prints the raw response body on stdout when given.
- Endpoint and API key come from `~/.config/tascade/config.toml`, overridden by
  `TASCADE_URL` / `TASCADE_API_KEY`, overridden by `--url` / `--api-key`.
- Console script `tascade = "app.cli.main:main"` registered in `pyproject.toml`.
- No new runtime dependencies. `urllib` and `tomllib` are stdlib.
- Out of scope, owned by other tasks: the brief, subprojects, the D4 task fields.
- `pytest -q` stays green.

### REST gaps closed by this task

`MCP_TOOL_NAMES` has 28 entries. Five have no REST equivalent, so a thin client cannot
reach them. Each is added here:

| MCP tool | New endpoint |
|---|---|
| `create_phase` | `POST /v1/phases` |
| `create_milestone` | `POST /v1/milestones` |
| `get_task_context` | `GET /v1/tasks/{task_id}/context` |
| `evaluate_gate_policies` | `POST /v1/gates/evaluate` |
| `get_instructions` | `GET /v1/instructions` |

The first two are named in the task scope; the last three are the same class of gap and are
already logged in `docs/BACKLOG.md` under "Carried forward". Without them the acceptance
criterion "every MCP tool has a CLI equivalent" is unreachable.

### Command table shape

```python
@dataclass(frozen=True)
class Arg:
    name: str                 # "--project-id" or positional "task_id"
    dest: str
    required: bool = False
    help: str = ""
    kind: str = "str"         # str | int | bool | json | list
    location: str = "body"    # body | query | path

@dataclass(frozen=True)
class Command:
    path: tuple[str, ...]     # ("tasks", "claim")
    method: str               # "POST"
    url: str                  # "/v1/tasks/{task_id}/claim"
    args: tuple[Arg, ...]
    mcp_tool: str | None      # name in MCP_TOOL_NAMES, or None for CLI-only
    help: str
```

## Task 3: HTTP client and rendering

**Files:**
- Create: `app/cli/client.py`, `app/cli/render.py`
- Test: `tests/test_cli_e2e.py` (client half)

**Interfaces:**
- Produces:
  - `class ApiError(Exception)` with `status: int`, `code: str`, `message: str`, `body: Any`.
  - `class ApiClient:` constructed as `ApiClient(config, transport=None)`.
    `request(method: str, path: str, query: dict | None = None, body: dict | None = None) -> Any`
    returns the decoded JSON body, raises `ApiError` for status >= 400.
  - `transport` is a callable `(method, url, headers, body_bytes) -> (status, bytes)`.
    Default is a `urllib.request` implementation. Tests inject a `TestClient`-backed one,
    which is how the CLI is exercised end to end without a live server.
  - `render(obj) -> str` in `render.py`: a dict with an `items` list renders one line per
    item using `short_id`/`id` plus `title`/`name`/`state` when present; any other dict
    renders as aligned `key: value` lines with nested values as compact JSON.
- Headers: `Content-Type: application/json`, and `Authorization: Bearer <api_key>` when a
  key is configured. `None` values are stripped from bodies and query strings before send.

def test_client_sends_bearer_and_body():
    seen = {}
    def transport(method, url, headers, body):
        seen.update(method=method, url=url, headers=headers, body=body)
        return 200, b'{"ok": true}'
    c = ApiClient(Config(url="http://h:1", api_key="k"), transport=transport)
    assert c.request("POST", "/v1/x", body={"a": 1, "b": None}) == {"ok": True}
    assert seen["headers"]["Authorization"] == "Bearer k"
    assert json.loads(seen["body"]) == {"a": 1}

def test_client_omits_auth_when_no_key():
    def transport(method, url, headers, body):
        assert "Authorization" not in headers
        return 200, b"{}"
    ApiClient(Config(url="http://h:1", api_key=None), transport=transport).request("GET", "/v1/x")

def test_client_raises_api_error_with_code():
    def transport(*_):
        return 409, b'{"detail": {"error": {"code": "LEASE_EXISTS", "message": "busy"}}}'
    with pytest.raises(ApiError) as exc:
        ApiClient(Config(url="http://h:1", api_key=None), transport=transport).request("POST", "/v1/x")
    assert exc.value.status == 409
    assert exc.value.code == "LEASE_EXISTS"
